ANALYSE DES FONCTIONS COMPILABLES:
===================================

Ces fonctions partagent des caractéristiques communes :
1. Utilisent principalement IF, LET, arithmétique simple
2. Utilisent MAPCAR mais avec fonctions lambda simples
3. N'utilisent PAS: SETF, GETHASH dans variables globales, CAR/CDR
4. Structures de données gérées via paramètres

EXEMPLE - COMPILE-EXPR (3263 instructions):
Cette fonction EST le cœur du compilateur et elle est compilable !
Elle utilise uniquement :
- COND avec tests =
- Appels récursifs
- Arithmétique simple
- Pas de CASE, pas de GETHASH sur globals

POURQUOI LES AUTRES ÉCHOUENT:
==============================

1. VARIABLES GLOBALES NON DÉFINIES (25+ fonctions)
   Exemple: COMPILE-CONSTANT utilise *REG-V0*
   → Ces variables EXISTENT mais ne sont pas chargées avant compilation
   → Solution: Charger asm-ops.lisp AVANT d'essayer de compiler

2. SETF SUR STRUCTURES COMPLEXES (10+ fonctions)
   Exemple: (SETF (COMPILER-ENV-STACK-OFFSET env) new-val)
   → SETF généralisé n'est pas supporté par le compilateur
   → Il faudrait transformer en appels de fonctions SET-XXX

3. LABELS AVEC SYMBOLES (15+ fonctions)
   Exemple: (LABEL 'LOOP_START) au lieu de (LABEL "LOOP_START")
   → Le compilateur génère des symboles, pas des strings
   → Solution: Modifier le parser/compiler pour convertir automatiquement

4. GETHASH SUR VARIABLES GLOBALES (5+ fonctions)
   Exemple: (GETHASH key *GLOBAL-CONSTANTS*)
   → Nécessite que *GLOBAL-CONSTANTS* existe au moment de la compilation
   → Mais aussi que GETHASH soit compilable

5. CAR/CDR/CONS NON SUPPORTÉS (20+ fonctions)
   → Le compilateur actuel ne sait PAS compiler ces opérations
   → Il faudrait les ajouter comme primitives VM

6. LOOP WHILE NON SUPPORTÉ (3+ fonctions)
   → Le parser LOOP ne gère que FOR ... TO/BELOW/IN
   → WHILE nécessiterait une extension

STRATÉGIES POSSIBLES:
=====================

STRATÉGIE A: DÉFINIR LES GLOBALS AVANT COMPILATION
---------------------------------------------------
Impact: ~25 fonctions supplémentaires (58% total)

Avant d'extraire les defuns, faire:
  (load "src/asm-ops.lisp")  ; Définit *REG-XX*
  (defvar *global-constants* (make-hash-table))
  (defvar *global-variables* (make-hash-table))
  etc.

Avantage: Simple, résout beaucoup d'erreurs
Inconvénient: Ne résout pas SETF, CAR/CDR, labels symboliques

STRATÉGIE B: TRANSFORMER LES FONCTIONS
---------------------------------------
Impact: Toutes les fonctions compilables potentiellement

Réécrire les fonctions pour utiliser uniquement:
- IF au lieu de COND complexe
- SETQ sur variables simples au lieu de SETF
- Strings pour labels au lieu de symboles
- Pas de CAR/CDR/CONS (passer les éléments séparément)

Avantage: Contrôle total, tout devient compilable
Inconvénient: Modifie les sources, lourd

STRATÉGIE C: ÉTENDRE LE COMPILATEUR
------------------------------------
Impact: Dépend de ce qu'on ajoute

Ajouter au compilateur (src/compiler.lisp):
- Support SETF généralisé
- Support CAR/CDR/CONS comme primitives
- Conversion automatique symboles → strings pour labels
- Support LOOP WHILE

Avantage: Améliore le compilateur pour de vrai
Inconvénient: Travail conséquent, et ces fonctions devront elles-mêmes
              être compilables
