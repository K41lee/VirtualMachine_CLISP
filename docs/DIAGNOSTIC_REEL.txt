2. CE QUI NE FONCTIONNE PAS
═══════════════════════════════════════════════════════════════════════

❌ EXÉCUTION DU CODE COMPILÉ
  - Erreur: "Adresse mémoire hors limites: 0"
  - Le PC démarre à 10480770 au lieu de l'adresse du code
  - La VM n'exécute pas les instructions générées

❌ PROBLÈME DU LOADER
  - Le code MIPS n'est PAS chargé en mémoire correctement
  - Format des instructions incompatible avec execute-instruction
  - Keywords (:ADDI, :$SP) vs symboles (ADDI, $SP)

❌ FORMAT DES INSTRUCTIONS
  Test d'exécution de (+ 2 3):
  
  Code chargé en mémoire:
    (:ADDI :$SP -8 :$SP)
    (:SW :$S7 :$SP 0)
    (:LI 2 :$V0)
    ...
  
  Problème: La VM s'attend à des symboles normaux, pas des keywords!
  
  La fonction execute-instruction recherche des patterns comme:
    (case (car instruction)
      (ADDI ...)   ← Symbole normal
      (LI ...)
      ...)
  
  Mais le code chargé contient:
    (:ADDI ...)  ← Keyword!
  
  Résultat: Aucune instruction n'est reconnue → PC=0 → crash

═══════════════════════════════════════════════════════════════════════
3. RAISON DU PROBLÈME
═══════════════════════════════════════════════════════════════════════

Le compilateur génère du code avec la fonction (list :ADDI ...) parce que
c'est défini ainsi dans compile-arithmetic, compile-cons, etc.

Exemple dans src/compiler.lisp ligne 865:
  (list :ADDI *reg-sp* -8 *reg-sp*)

Ce code retourne une liste avec un KEYWORD comme premier élément.

La VM (src/vm.lisp) attend des SYMBOLES:
  (case (car instruction)
    (ADDI ...)    ← Cherche le symbole ADDI, pas le keyword :ADDI
    ...)
