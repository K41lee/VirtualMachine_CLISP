1. CONTEXTE
=================================================================================

L'instruction LIST permet à la VM d'exécuter du code compilé qui crée des 
structures de données Lisp (listes). Elle est essentielle pour le bootstrap 
car le compilateur, une fois chargé dans la VM, doit pouvoir créer des listes
pour construire le code assembleur généré.

ARCHITECTURE:
  - Délégation à Lisp: Les structures de données sont gérées par Lisp natif
  - Système de handles: Les objets Lisp sont référencés par des IDs uniques
  - Tables globales:
    * *vm-lisp-objects*: Hash table (handle → objet Lisp)
    * *vm-lisp-handle-counter*: Générateur d'IDs uniques

=================================================================================
2. SPÉCIFICATION DE L'INSTRUCTION
=================================================================================

FORMAT:
  (LIST count)
  OU
  (:LIST count)

OPÉRANDE:
  count: Nombre d'éléments à lire depuis la pile

COMPORTEMENT:
  1. Lit 'count' éléments depuis la pile
  2. Crée une liste Lisp native avec ces éléments
  3. Génère un handle unique
  4. Stocke la liste dans *vm-lisp-objects*
  5. Retourne le handle dans $V0
  6. Dépile les éléments (restaure $SP)

REGISTRES:
  Entrée:  $SP (pointeur de pile)
  Sortie:  $V0 (handle de la liste créée)
  Modifié: $SP (incrémenté de count)

PILE:
  Les éléments sont empilés dans l'ordre avec PUSH.
  $SP pointe sur le prochain emplacement libre (après le dernier élément).
  LIST lit à partir de $SP+1, $SP+2, ..., $SP+count.

ORDRE:
  Si on fait PUSH(A), PUSH(B), LIST(2), on obtient la liste (A B).

=================================================================================
3. IMPLÉMENTATION
=================================================================================

FICHIER: src/vm.lisp (lignes 879-896)

CODE:
  ((LIST :LIST)
   (let* ((count (first args))
          (elements nil))
     ;; Récupérer les éléments de la pile
     ;; $SP pointe sur le prochain emplacement libre, donc on lit à partir de $SP+1
     (dotimes (i count)
       (let* ((addr (+ (get-value vm :$sp) i 1))
              (val (mem-read vm addr)))
         ;; Résoudre le handle si c'est un objet Lisp
         (push (gethash val *vm-lisp-objects* val) elements)))
     ;; Restaurer la pile (dépiler count éléments)
     (set-value vm :$sp (+ (get-value vm :$sp) count))
     ;; Créer la liste et son handle
     (let ((result-list elements)
           (handle (incf *vm-lisp-handle-counter*)))
       (setf (gethash handle *vm-lisp-objects*) result-list)
       (set-value vm :$v0 handle)
       (when (vm-verbose vm)
         (format t "  LIST(~A): ~A -> handle ~A~%" count result-list handle)))))

ARITÉ: 1 argument (défini dans src/asm-ops.lisp ligne 196)

OPCODE: :LIST présent dans *opcodes* (src/asm-ops.lisp ligne 52)

6. PROBLÈMES RÉSOLUS
=================================================================================

PROBLÈME 1: "Opcode invalide: LIST"
  Cause:    Code source utilisait des symboles (LIST) au lieu de keywords (:LIST)
  Solution: Utiliser la syntaxe keyword correcte dans le code de test

PROBLÈME 2: Liste incorrecte ((PUSH $V0) 0) au lieu de (43 42)
  Cause:    Mauvais calcul d'adresse - offset * 4 au lieu de offset + 1
  Solution: Corriger l'adressage: $SP+1, $SP+2, ..., $SP+count

PROBLÈME 3: Terminal crashé lors des tests
  Cause:    Tests répétés avec timeouts
  Solution: Créer des tests simples et ciblés avec sortie limitée

  Solution: Utiliser make-new-vm qui initialise les registres

7. ARCHITECTURE DES HANDLES
=================================================================================

TABLES GLOBALES:
  *vm-lisp-objects*: (make-hash-table :test 'eql)
    - Clé:   Handle (entier unique)
    - Valeur: Objet Lisp (liste, string, etc.)
  
  *vm-lisp-handle-counter*: Compteur global (débute à 5000)

CYCLE DE VIE:
  1. Création:  (incf *vm-lisp-handle-counter*)
  2. Stockage:  (setf (gethash handle *vm-lisp-objects*) object)
  3. Lecture:   (gethash handle *vm-lisp-objects* default)
  4. Résolution: (gethash val *vm-lisp-objects* val)

ISOLATION:
  Chaque objet a un handle unique. Les objets sont isolés même si leurs
  valeurs sont identiques.
