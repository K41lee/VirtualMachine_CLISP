FONCTION 1: PREPROCESS-CODE
----------------------------
Problème initial:
  "Variable non définie: LABELS"

Cause:
  La fonction utilisait 'labels' comme nom de variable locale,
  mais resolve-labels attend un paramètre nommé 'labels-hash'.
  Conflit de nommage dans le let initial.

Solution appliquée:
  (defun preprocess-code (asm-code code-start)
    (let ((labels-hash (collect-labels asm-code code-start))
          (resolved nil))
      ;; D'abord collecter les labels
      (setq labels-hash (collect-labels asm-code code-start))
      ;; Ensuite résoudre avec la hash-table
      (setq resolved (resolve-labels asm-code labels-hash))
      ;; Retourner (resolved-code . labels-hash)
      (vm-cons resolved labels-hash)))

Changements:
  1. Renommé 'labels' → 'labels-hash' (clarté et cohérence)
  2. Ajouté 'resolved' comme variable séparée (initialisée à nil)
  3. Utilisé setq explicites (meilleure compatibilité compilation)
  4. Évite l'initialisation directe dans let qui causait l'erreur

Résultat:
  ✅ Compile en 78 instructions MIPS


FONCTION 2: LOAD-CODE-COMPILABLE
---------------------------------
Problème initial:
  "Variable non définie: PREPROCESSED"

Cause:
  La fonction initialisait 'resolved-code' avec (vm-car preprocessed)
  directement dans le let, mais le compilateur ne pouvait pas
  résoudre l'ordre des dépendances.

Solution appliquée:
  (defun load-code-compilable (asm-code code-start)
    "Charge du code assembleur dans la VM après résolution des labels.
     Note: mem-write écrit dans la VM courante (primitive VM)."
    (let ((preprocessed (preprocess-code asm-code code-start))
          (resolved-code nil)
          (addr code-start))
      ;; Extraire le code résolu
      (setq resolved-code (vm-car preprocessed))
      ;; Charger chaque instruction en mémoire
      (dolist (instr resolved-code)
        (mem-write addr instr)
        (setq addr (+ addr 1)))
      code-start))

Changements:
  1. Retiré paramètre 'vm' inutilisé (mem-write est une primitive VM)
  2. Initialisé 'resolved-code' à nil dans let
  3. Utilisé setq explicite pour extraire avec vm-car
  4. Ajouté documentation sur mem-write (primitive VM)

Résultat:
  ✅ Compile en 79 instructions MIPS

LEÇON APPRISE:
--------------
Pour rendre du code Lisp compilable en MIPS, préférer:

✅ BONNES PRATIQUES:
  1. Initialiser variables let à nil ou valeur simple
  2. Utiliser setq explicite pour assignations complexes
  3. Éviter calculs dans initialisations let
  4. Noms de variables clairs et distincts
  5. Séparer collection et utilisation de données

❌ À ÉVITER:
  1. let avec expressions complexes d'initialisation
  2. Noms de variables ambigus (labels vs labels-hash)
  3. Dépendances circulaires dans let
  4. Paramètres non utilisés dans signature de fonction

EXEMPLE:

Avant (NON compilable):
  (let ((labels (collect-labels ...))
        (resolved (resolve-labels ... labels)))  ; ← labels pas encore défini!
    ...)

Après (compilable):
  (let ((labels-hash nil)
        (resolved nil))
    (setq labels-hash (collect-labels ...))      ; ← séquentiel, clair
    (setq resolved (resolve-labels ... labels-hash))
    ...)
