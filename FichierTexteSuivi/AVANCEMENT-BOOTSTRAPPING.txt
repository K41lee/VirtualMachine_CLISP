NOTES ET DÉCISIONS TECHNIQUES
═══════════════════════════════════════════════════════════════════

DÉCISION 1 : Délégation à Lisp
  • Rationale : Simplifier l'implémentation, réutiliser l'existant
  • Impact : Pas de code MIPS généré, structures en Lisp
  • Avantage : Rapide à implémenter, fiable
  • Inconvénient : Dépendance à l'environnement Lisp

DÉCISION 2 : Handles pour instances
  • Rationale : Référencer les instances depuis le code MIPS
  • Impact : Les handles sont des entiers
  • Avantage : Simple, efficace
  • Inconvénient : Nécessite GC éventuel

DÉCISION 3 : Pas de code d'initialisation généré
  • Rationale : Structures définies manuellement dans l'environnement
  • Impact : defstruct ne génère pas de code MIPS
  • Avantage : Simplicité
  • Inconvénient : Nécessite initialisation manuelle
