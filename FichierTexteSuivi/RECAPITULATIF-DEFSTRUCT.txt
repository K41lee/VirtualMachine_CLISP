OBJECTIF
═══════════════════════════════════════════════════════════════════

Implémenter DEFSTRUCT pour permettre au compilateur de se compiler
lui-même. Le compilateur utilise (defstruct compiler-env ...) avec
9 slots et ~50 utilisations des accesseurs.

═══════════════════════════════════════════════════════════════════
APPROCHE CHOISIE : DÉLÉGATION À LISP
═══════════════════════════════════════════════════════════════════

Au lieu de générer du code MIPS complexe, on délègue la gestion
des structures à l'environnement Lisp via des primitives VM :

  1. Structures stockées dans hash-tables côté Lisp
  2. Instances identifiées par handles (entiers)
  3. Code compilé manipule les handles
  4. Primitives VM font le vrai travail

Même approche que pour hash-tables et listes !

═══════════════════════════════════════════════════════════════════
EXEMPLE D'UTILISATION
═══════════════════════════════════════════════════════════════════

;; 1. Définir la structure dans la VM
(vm-defstruct *vm* 'COMPILER-ENV 
              '(VARIABLES FUNCTIONS LABEL-COUNTER 
                TEMP-REGS-AVAILABLE MAX-TEMP-REGS STACK-OFFSET 
                PARENT-ENV LEXICAL-DEPTH PARENT-LEXICAL))

;; 2. Charger les accesseurs
(load "src/compiler-env-accessors.lisp")

;; 3. Créer une instance
(defparameter *env* 
  (make-compiler-env :max-temp-regs 3
                     :temp-regs-available '($t0 $t1 $t2)))

;; 4. Utiliser les accesseurs
(compiler-env-max-temp-regs *env*)  ; → 3
(setf (compiler-env-variables *env*) '((x . $t0)))
(compiler-env-variables *env*)  ; → ((X . $T0))

;; 5. Afficher pour débogage
(print-compiler-env *env*)

OPTION 1 : Utilisation directe (RECOMMANDÉ pour bootstrapping)
  1. Charger vm-primitives-structs.lisp dans l'environnement
  2. Charger compiler-env-accessors.lisp
  3. Définir COMPILER-ENV dans la VM
  4. Le compilateur peut maintenant utiliser les accesseurs

OPTION 2 : Génération automatique des accesseurs
  • Implémenter la macroexpansion de defstruct
  • Générer automatiquement make-xxx, xxx-p, xxx-slot
  • Plus complexe, pour une version future

Pour le bootstrapping immédiat, Option 1 suffit !
