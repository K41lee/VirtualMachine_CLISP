STRATÉGIE D'IMPLÉMENTATION
═══════════════════════════════════════════════════════════════════

APPROCHE : Transformation en code Lisp simple

Au lieu de compiler LOOP directement en MIPS, on le transforme
en constructions déjà supportées (LET, WHILE, PROGN, etc).

EXEMPLE 1 : (loop for i from 1 to 10 do body)
  Transformer en :
  (let ((i 1))
    (while (<= i 10)
      body
      (setq i (+ i 1))))

EXEMPLE 2 : (loop for x in list do body)
  Transformer en :
  (let ((#:list-temp list))
    (while #:list-temp
      (let ((x (car #:list-temp)))
        body
        (setq #:list-temp (cdr #:list-temp)))))

EXEMPLE 3 : (loop for x in list collect expr)
  Transformer en :
  (let ((#:result nil)
        (#:list-temp list))
    (while #:list-temp
      (let ((x (car #:list-temp)))
        (setq #:result (cons expr #:result))
        (setq #:list-temp (cdr #:list-temp))))
    (reverse #:result))

AVANTAGES :
  ✓ Réutilise le code existant (let, while, setq, etc)
  ✓ Pas de nouveau code MIPS à générer
  ✓ Plus simple et plus rapide à implémenter
  ✓ Facile à déboguer

INCONVÉNIENTS :
  ✗ Performance moindre (plus d'instructions)
  ✗ Nécessite gensym pour variables temporaires

Pour le bootstrapping, les avantages l'emportent !

GENSYM POUR VARIABLES TEMPORAIRES
═══════════════════════════════════════════════════════════════════

PROBLÈME : Les transformations ont besoin de variables temporaires
           uniques pour éviter les conflits de noms.

SOLUTION : Implémenter gensym simple côté compilation

(defparameter *gensym-counter* 0)

(defun compiler-gensym (&optional (prefix "G"))
  "Génère un symbole unique pour le compilateur."
  (incf *gensym-counter*)
  (intern (format nil "~A~A" prefix *gensym-counter*)))

Exemples :
  (compiler-gensym "LIST")  → LIST1
  (compiler-gensym "RESULT") → RESULT2
  (compiler-gensym)          → G3

EXEMPLE COMPLET : TRANSFORMATION
═══════════════════════════════════════════════════════════════════

CODE ORIGINAL (ligne 3486 du compilateur) :
  (loop for arg in args
        for reg in arg-regs
        do (let ((arg-code (compile-expr arg env)))
             (setf code (append code
                               arg-code
                               (list (list :MOVE *reg-v0* reg))))))

PARSING :
  (:loop-for
    :clauses ((:for arg :in args)
              (:for reg :in arg-regs))
    :action :do
    :body ((let ((arg-code (compile-expr arg env)))
             (setf code ...))))

EXPANSION :
  (let ((#:list-temp1 args)
        (#:list-temp2 arg-regs))
    (while (and #:list-temp1 #:list-temp2)
      (let ((arg (car #:list-temp1))
            (reg (car #:list-temp2)))
        (let ((arg-code (compile-expr arg env)))
          (setf code (append code
                            arg-code
                            (list (list :MOVE *reg-v0* reg)))))
        (setq #:list-temp1 (cdr #:list-temp1))
        (setq #:list-temp2 (cdr #:list-temp2)))))

COMPILATION :
  Le code expansé est ensuite compilé normalement avec
  compile-expr, qui sait déjà gérer let, while, setq, etc.
