2. BUGS DÉCOUVERTS ET CORRIGÉS
═══════════════════════════════════════════════════════════════════════════════

2.1 Bug #1 : PROGN + DEFUN ne parsait pas les lambda-lists
────────────────────────────────────────────────────────────
Symptôme : "Too few arguments (4 instead of at least 5) given to COMPILE-DEFUN"
Cause : compile-progn traitait DEFUN manuellement sans appeler parse-lisp-expr
Localisation : src/compiler.lisp, lignes 1735-1755
Solution : Parser le DEFUN avant de compiler
  AVANT : (compile-defun name params body env)
  APRÈS : (let ((parsed (parse-lisp-expr expr)))
            (compile-defun name params body parsed-params env))

2.2 Bug #2 : Loader non chargé dans les tests
──────────────────────────────────────────────
Symptôme : "undefined function LOAD-AND-RUN"
Cause : test-self-compilation.lisp ne chargeait que vm.lisp et compiler.lisp
Solution : Ajouter (load "src/loader.lisp") entre vm et compiler

2.3 Bug #3 : test-compilation-and-execution retournait la VM, pas $V0
──────────────────────────────────────────────────────────────────────
Symptôme : Tests comparaient une VM à une valeur numérique
Solution : Extraire la valeur de $V0 :
  (let* ((vm (compile-and-run combined-expr))
         (result (get-register vm :$V0)))
    ...)

2.4 Amélioration : Support FIRST/REST/SECOND
─────────────────────────────────────────────
Ajout des alias Common Lisp pour CAR/CDR/CADR
Localisation : src/compiler.lisp, lignes 433-453
  (first ...) → (:car ...)
  (rest ...)  → (:cdr ...)
  (second ..) → (:car (:cdr ...))

4. DÉCOUVERTE CRITIQUE : LIMITATION DE LA VM
═══════════════════════════════════════════════════════════════════════════════

🔴 PROBLÈME MAJEUR IDENTIFIÉ 🔴

La VM ne supporte PAS les structures de données LISP en mémoire.

4.1 Symptômes observés
──────────────────────
• (null (quote (a b c))) retourne (a b c) au lieu de 0 (faux)
• (car (quote (a b c))) retourne (a b c) au lieu de 'a
• (count-elements (quote (a b c d e))) retourne (a b c d e) au lieu de 5
• Les fonctions récursives sur listes retournent toujours leur argument

4.2 Analyse technique
─────────────────────
Représentation actuelle :
  • (quote (a b c)) → (:constant (a b c))
  • Compilé comme une valeur S-expression Lisp
  • Chargée directement dans $V0 comme objet Lisp
  • PAS stockée en mémoire comme structure de données

Opérations CAR/CDR/CONS :
  • compile-car génère : (LW $V0 $V0 0)  ; Charge mot à offset 0
  • compile-cdr génère : (LW $V0 $V0 1)  ; Charge mot à offset 1
  • MAIS $V0 contient une S-expression, pas une adresse mémoire !
  • LW échoue ou retourne des valeurs incorrectes

Pourquoi factorial fonctionne mais count-elements ne fonctionne pas :
  • factorial : Manipulation de NOMBRES uniquement
    (factorial 5) → (* 5 (factorial 4)) → nombres en registres
  • count-elements : Manipulation de LISTES
    (count-elements '(a b c)) → (rest lst) nécessite accès mémoire

4.3 Ce qui fonctionne
─────────────────────
✓ Arithmétique (+ - * / mod)
✓ Comparaisons (< > = <= >=)
✓ Logique (and or not)
✓ Conditions (if cond when unless)
✓ Boucles (loop while dotimes)
✓ Variables locales (let let*)
✓ Fonctions (defun) avec appels récursifs
✓ Paramètres avancés (&optional &key &rest)

4.4 Ce qui NE fonctionne PAS
────────────────────────────
✗ Construction de listes : (cons 'a '(b c))
✗ Décomposition : (car lst) (cdr lst)
✗ Tests : (null lst) (listp lst)
✗ Manipulation : (append lst1 lst2) (member x lst)
✗ Itération : (dolist (x lst) ...)
✗ Toute opération nécessitant des listes en mémoire

5. IMPLICATIONS POUR L'AUTO-COMPILATION
═══════════════════════════════════════════════════════════════════════════════

5.1 Parties du compilateur NON compilables
───────────────────────────────────────────
Ces fonctions manipulent des listes et ne peuvent PAS être compilées :

• free-variables : Analyse récursive des variables libres
  - Utilise : car, cdr, append, mapcan
  - Entrée/sortie : Listes de symboles

• extract-first-elements, extract-second-elements : Helpers de bootstrapping
  - Récursion sur listes
  - Retournent des listes

• parse-lisp-expr : Parser principal
  - Décompose des S-expressions
  - Retourne des listes structurées

• compile-expr : Compilateur principal
  - Pattern matching sur listes
  - Retourne du code (liste d'instructions)

• Toutes les fonctions de manipulation d'environnement
  - get-hash, set-hash utilisent des hash-tables
  - Les environnements sont des structures complexes

5.2 Parties du compilateur POTENTIELLEMENT compilables
───────────────────────────────────────────────────────
Ces fonctions manipulent principalement des NOMBRES :

✓ compile-arithmetic : Génération d'opérations arithmétiques
  - Manipule des registres (indices numériques)
  - Peu de manipulation de listes

✓ compile-comparison : Génération de comparaisons
  - Idem, principalement numérique

✓ gen-label : Génération de labels
  - Retourne des symboles (mais pas de récursion sur listes)

✓ Certaines optimisations locales
  - Ne manipulent que des nombres et registres

6. SOLUTIONS POSSIBLES
═══════════════════════════════════════════════════════════════════════════════

6.1 Solution complète (plusieurs semaines)
───────────────────────────────────────────
Implémenter un système de gestion mémoire complet :

A) Heap allocation
   • Réserver une zone mémoire pour le tas (heap)
   • Implémenter malloc/free en MIPS
   • Allouer des cons cells (2 mots : CAR + CDR)

B) Représentation des listes
   • Liste = adresse mémoire d'une cons cell
   • NIL = 0 (adresse nulle)
   • (cons a b) alloue 2 mots et retourne l'adresse
   • (car addr) charge le mot à offset 0
   • (cdr addr) charge le mot à offset 1

C) Garbage Collection
   • Mark-and-sweep ou reference counting
   • Libérer la mémoire non utilisée
   • Compacter le heap

D) Compilation des constantes listes
   • (quote (a b c)) → Construire en mémoire statique
   • Générer du code d'initialisation
   • Retourner l'adresse

E) Gestion des symboles
   • Table de symboles globale
   • Interning des symboles
   • Comparaison d'identité

Temps estimé : 3-4 semaines
Complexité : Très élevée
Risque : Beaucoup de bugs potentiels

6.2 Solution intermédiaire (1 semaine)
───────────────────────────────────────
Implémenter un sous-ensemble minimal :

• Support des listes de nombres uniquement
• Pas de symboles (sauf NIL)
• Pas de GC (fuite mémoire acceptable pour tests)
• Heap simple avec bump allocator
• Cons/car/cdr/null pour nombres

Permet de tester :
  ✓ Récursion sur listes de nombres
  ✓ Fonctions helpers avec listes
  ✗ Manipulation de symboles (parse-lisp-expr impossible)

6.3 Solution pragmatique (1-2 jours)
─────────────────────────────────────
Abandonner l'auto-compilation complète et se concentrer sur :

A) Compilation partielle
   • Compiler les fonctions qui manipulent des nombres
   • Valider que le compilateur GÉNÈRE du code correct
   • Ne PAS exécuter le code généré sur des listes

B) Tests de génération de code
   • Vérifier que parse-lisp-expr GÉNÈRE le bon AST
   • Vérifier que compile-expr GÉNÈRE les bonnes instructions
   • Comparer avec des résultats attendus (snapshots)

C) Documentation et démonstration
   • Documenter les limitations
   • Montrer ce qui fonctionne (96.6% de support)
   • Expliquer pourquoi l'auto-compilation complète nécessite une VM avancée
