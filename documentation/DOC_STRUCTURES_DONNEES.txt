ARCHITECTURE DU SYSTÈME
═══════════════════════════════════════════════════════════════════════════════

Le système utilise une approche hybride pour gérer les structures de données:

1. **HANDLES** (Pointeurs abstraits):
   - Les objets Lisp complexes (listes, symboles, etc.) sont stockés dans
     une hash-table Lisp: *vm-lisp-objects*
   - La VM manipule des "handles" (entiers) qui référencent ces objets
   - Handle 0 = NIL (liste vide)
   - Handle > 0 = Référence à un objet Lisp

2. **INSTRUCTIONS VM SPÉCIALES**:
   - LIST-CAR, LIST-CDR, LIST-CONS: Opérations sur listes
   - LISP-OBJECT: Crée un handle vers un objet quoté (à implémenter dans loader)
   - EQUAL: Comparaison profonde d'objets Lisp

3. **COMPILATION**:
   - Le compilateur génère des instructions LIST-xxx au lieu de gérer
     directement les structures
   - Les fonctions compile-car-simplified, compile-cdr-simplified, etc.
     sont déjà implémentées

✅ **NULL** - Test si une valeur est NIL
   - Syntaxe: (null expr)
   - Test: NULL fonctionne avec (null 0) → vrai, (null 42) → faux
   - Résultat: Retourne 1 (vrai) ou 0 (faux)

✅ **QUOTE** (compilation uniquement)
   - Syntaxe: (quote expr) ou 'expr
   - Compilation: Génère :LISP-OBJECT pour objets non-numériques
   - Status: Compile mais nécessite support dans le loader

✅ **CAR** (compilation uniquement)
   - Syntaxe: (car liste)
   - Compilation: Génère :LIST-CAR instruction
   - VM: Implémentée dans execute-instruction
   - Status: Prêt mais nécessite loader pour créer les listes

✅ **CDR** (compilation uniquement)
   - Syntaxe: (cdr liste)
   - Compilation: Génère :LIST-CDR instruction
   - VM: Implémentée dans execute-instruction
   - Status: Prêt mais nécessite loader pour créer les listes

✅ **CONS** (compilation uniquement)
   - Syntaxe: (cons a b)
   - Compilation: Génère :LIST-CONS instruction
   - VM: Implémentée dans execute-instruction
   - Status: Prêt mais nécessite intégration complète

✅ **FIRST/REST** - Aliases de CAR/CDR
   - Syntaxe: (first liste), (rest liste)
   - Status: Compile correctement

ALGORITHMES POSSIBLES AVEC CES STRUCTURES
═══════════════════════════════════════════════════════════════════════════════

Avec l'infrastructure actuelle (une fois LISP-OBJECT implémenté):

1. **LONGUEUR DE LISTE** (récursive):
   ```lisp
   (defun my-length (lst)
     (if (null lst)
         0
         (+ 1 (my-length (cdr lst)))))
   ```

2. **SOMME D'UNE LISTE**:
   ```lisp
   (defun sum-list (lst)
     (if (null lst)
         0
         (+ (car lst) (sum-list (cdr lst)))))
   ```

3. **REVERSE D'UNE LISTE**:
   ```lisp
   (defun my-reverse (lst)
     (if (null lst)
         nil
         (append (my-reverse (cdr lst)) (list (car lst)))))
   ```

4. **MEMBRE (recherche dans liste)**:
   ```lisp
   (defun member-rec (x lst)
     (if (null lst)
         nil
         (if (= x (car lst))
             t
             (member-rec x (cdr lst)))))
   ```

5. **MAP (appliquer fonction à liste)**:
   ```lisp
   (defun map-inc (lst)
     (if (null lst)
         nil
         (cons (+ 1 (car lst)) (map-inc (cdr lst)))))
   ```

6. **FILTER (filtrer liste)**:
   ```lisp
   (defun filter-positifs (lst)
     (if (null lst)
         nil
         (if (> (car lst) 0)
             (cons (car lst) (filter-positifs (cdr lst)))
             (filter-positifs (cdr lst)))))
   ```

7. **QUICKSORT (tri récursif)**:
   ```lisp
   (defun quicksort (lst)
     (if (null lst)
         nil
         (let ((pivot (car lst))
               (rest (cdr lst)))
           (append (quicksort (filter-smaller rest pivot))
                   (list pivot)
                   (quicksort (filter-larger rest pivot))))))
   ```

8. **MERGE (fusion de listes triées)**:
   ```lisp
   (defun merge-sorted (l1 l2)
     (if (null l1) l2
         (if (null l2) l1
             (if (< (car l1) (car l2))
                 (cons (car l1) (merge-sorted (cdr l1) l2))
                 (cons (car l2) (merge-sorted l1 (cdr l2)))))))
   ```

9. **PARCOURS D'ARBRE (DFS)**:
   ```lisp
   ;; Arbre représenté comme (valeur . (gauche . droite))
   (defun tree-dfs (tree)
     (if (null tree)
         0
         (+ (car tree)
            (tree-dfs (car (cdr tree)))
            (tree-dfs (cdr (cdr tree))))))
   ```

10. **PERMUTATIONS**:
    ```lisp
    (defun insert-all (x lst)
      (if (null lst)
          (list (list x))
          (cons (cons x lst)
                (insert-all x (cdr lst)))))
    
    (defun permutations (lst)
      (if (null lst)
          (list nil)
          (mapcan (lambda (x) (insert-all (car lst) x))
                  (permutations (cdr lst)))))
    ```

ALGORITHMES DE GRAPHE POSSIBLES
═══════════════════════════════════════════════════════════════════════════════

Graphe représenté comme liste d'adjacence:
- '((1 . (2 3)) (2 . (3 4)) (3 . (4)) (4 . NIL))
  Signifie: 1→2,3  2→3,4  3→4  4→∅

1. **DFS (Depth-First Search)**:
   ```lisp
   (defun dfs (graph node visited)
     (if (member node visited)
         visited
         (let ((neighbors (cdr (assoc node graph))))
           (fold-dfs neighbors (cons node visited) graph))))
   ```

2. **BFS (Breadth-First Search)**:
   - Nécessite une file (queue)
   - Peut être implémentée avec 2 listes (front/back)

3. **CHEMIN DANS GRAPHE**:
   ```lisp
   (defun find-path (graph start end)
     (if (= start end)
         (list end)
         (find-path-aux graph start end nil)))
   ```
