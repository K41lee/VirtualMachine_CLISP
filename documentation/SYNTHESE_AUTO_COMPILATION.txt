4. POURQUOI 30% ET PAS 100% ?
═══════════════════════════════════════════════════════════════

Les 75 fonctions non compilables utilisent des constructions
avancées que le compilateur bootstrap ne supporte pas (encore):

CATÉGORIE 1: LABELS SYMBOLIQUES (15+ fonctions)
----------------------------------------------
Problème: (LABEL 'LOOP_START) au lieu de (LABEL "LOOP_START")
Exemples: COMPILE-IF, COMPILE-COND, COMPILE-WHEN, etc.

Le compilateur génère des symboles pour les labels mais le
bootstrap attend des strings.

Solution: Modifier le compilateur pour accepter les deux formats

CATÉGORIE 2: SETF SUR STRUCTURES (10+ fonctions)
----------------------------------------------
Problème: (SETF (COMPILER-ENV-STACK-OFFSET env) val)
Exemples: ALLOC-STACK-SLOT, FREE-STACK-SLOTS, etc.

SETF généralisé n'est pas supporté par le bootstrap.

Solution: Transformer en appels de fonctions SET-XXX ou
         étendre le compilateur pour supporter SETF

CATÉGORIE 3: PRIMITIVES LISTE (20+ fonctions)
-------------------------------------------
Problème: CAR, CDR, CONS, LIST, APPEND utilisés directement
Exemples: GEN-LABEL, FREE-VARIABLES, COMPILE-CONS, etc.

Ces primitives ne sont pas compilables avec le bootstrap actuel.

Solution: Ajouter ces primitives comme opérations VM natives

CATÉGORIE 4: VARIABLES GLOBALES DANS SETQ (10+ fonctions)
-------------------------------------------------------
Problème: (SETQ (CAR *counter*) ...) ou (SETQ var1 val1 var2 val2)
Exemples: GEN-LABEL, RESET-GLOBAL-TABLES, etc.

SETQ avec expressions complexes non supporté.

Solution: Simplifier le code ou étendre SETQ

CATÉGORIE 5: LOOP WHILE (3+ fonctions)
------------------------------------
Problème: (LOOP WHILE condition DO ...)
Exemples: DUMP-CODE, LOOKUP-FUNCTION-DEF-INFO, etc.

Le parser LOOP ne gère que FOR ... TO/BELOW/IN.

Solution: Étendre le parser LOOP

CATÉGORIE 6: PRÉDICATS ET TESTS (10+ fonctions)
---------------------------------------------
Problème: EQ, LISTP, INTEGERP, SYMBOLP utilisés
Exemples: FREE-VARIABLES-LIST, PARSE-ASM, etc.

Ces prédicats de type ne sont pas implémentés.

Solution: Ajouter ces primitives au bootstrap

5. ARCHITECTURE COMPILABLE
═══════════════════════════════════════════════════════════════

Les 33 fonctions compilables suivent ces règles:

✓ Utilisent IF, COND (avec tests simples =, <, >)
✓ Utilisent LET, LET* pour bindings locaux
✓ Utilisent +, -, *, / pour arithmétique
✓ Utilisent DEFUN standard (pas de &optional, &rest, &key avancés)
✓ Appellent d'autres fonctions (récursion supportée)
✓ Utilisent MAPCAR avec fonctions lambda simples
✓ Pas de SETF, CAR/CDR, GETHASH, SETQ complexe
✓ Pas de labels symboliques générés dynamiquement

EXEMPLE - COMPILE-EXPR (simplifié):
```lisp
(defun compile-expr (parsed-node env)
  (let ((node-type-id (get-parsed-type-id parsed-node)))
    (cond
      ((= node-type-id *number-id*)
       (compile-number ...))
      ((= node-type-id *symbol-id*)
       (compile-symbol ...))
      ((= node-type-id *call-id*)
       (compile-call ...))
      (t
       (error "Unknown node type")))))
```

Cette fonction:
- Utilise LET pour binding local
- Utilise COND avec tests d'égalité
- Fait des appels récursifs
- Pas de structures de données complexes
→ Parfaitement compilable !

6. STRATÉGIES POUR ATTEINDRE 100%
═══════════════════════════════════════════════════════════════

OPTION A: EXTENSION DU COMPILATEUR (Recommandé)
-------------------------------------------------
Impact: Peut rendre 50-70% supplémentaires compilables

Ajouts nécessaires au src/compiler.lisp:

1. Support labels symboliques:
   Modifier gen-label et label handling pour accepter symboles
   et les convertir automatiquement en strings

2. Support SETF basique:
   (SETF (accessor obj) val) → (set-accessor obj val)

3. Support primitives liste:
   CAR, CDR, CONS, LIST comme appels VM natifs
   (similaire à COMPILE-VM-PRIMITIVE)

4. Support prédicats:
   LISTP, INTEGERP, SYMBOLP, EQ comme primitives VM

5. Étendre LOOP:
   Ajouter support WHILE dans parser-loop.lisp

Avantages:
+ Améliore vraiment le compilateur
+ Les extensions sont elles-mêmes compilables
+ Approche propre et maintenable

Inconvénients:
- Travail conséquent (~1-2 jours)
- Nécessite tests approfondis

OPTION B: SIMPLIFICATION DES FONCTIONS
---------------------------------------
Impact: Peut rendre 80-90% compilables

Réécrire les fonctions qui échouent pour:
- Remplacer SETF par fonctions set-XXX
- Remplacer CAR/CDR par accès direct ou paramètres séparés
- Utiliser strings pour labels
- Éviter LOOP WHILE, utiliser recursion

Avantages:
+ Contrôle total sur la compilabilité
+ Peut atteindre ~90%

Inconvénients:
- Modifie les sources originales
- Perte de lisibilité
- Maintenance difficile

OPTION C: ACCEPTER 30% ET DOCUMENTER
--------------------------------------
Impact: Aucune action nécessaire

30% représente déjà un succès significatif car:
- COMPILE-EXPR (le cœur) est compilable
- Beaucoup de fonctions utilitaires compilables
- 9099 instructions MIPS générées
- Démontre que l'architecture fonctionne

Avantages:
+ Aucun travail supplémentaire
+ Résultats déjà impressionnants

Inconvénients:
- Pas de "bootstrap complet à 100%"
- 70% des fonctions non exploitables en VM
