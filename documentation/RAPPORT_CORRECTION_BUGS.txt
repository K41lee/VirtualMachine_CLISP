BUG #1: MOD retournait l'input au lieu du reste
────────────────────────────────────────────────────────────────────────────
Symptôme:
  - sum-digits(123) retournait 123 au lieu de 6
  - (mod 123 10) retournait 123 au lieu de 3

Cause:
  - L'opérateur 'mod n'était PAS reconnu dans compile-call-simplified
  - Le compilateur générait un appel de fonction JAL "MOD" au lieu d'inline
  - La fonction MOD n'existait pas, donc retournait l'argument

Fichier: src/compiler-simplified.lisp
Ligne: 1142

Code problématique:
```lisp
((eq op '/) (compile-arithmetic-simplified "/" args env))
((eq op '%) (compile-arithmetic-simplified "%" args env))
;; MOD manquant!

;; Comparaisons
```

Solution appliquée:
```lisp
((eq op '/) (compile-arithmetic-simplified "/" args env))
((eq op '%) (compile-arithmetic-simplified "%" args env))
((eq op 'mod) (compile-arithmetic-simplified "%" args env))  ; ← AJOUTÉ

;; Comparaisons
```

Résultat:
  ✅ sum-digits(123) = 6 maintenant correct
  ✅ (mod n 10) génère maintenant DIV + MFHI inline


BUG #2: Tribonacci retournait 24 au lieu de 44
────────────────────────────────────────────────────────────────────────────
Symptôme:
  - tribonacci(8) retournait 24 au lieu de 44

Cause:
  - ERREUR dans le test lui-même!
  - Code du test: (if (<= n 1) 0 ...)  → Retourne 0 pour n=0 et n=1
  - Code correct: (if (< n 2) n ...)   → Retourne n pour n=0 et n=1
  
Vérification Lisp natif:
  - (if (<= n 1) 0 ...) pour n=8 → 24 ✅
  - (if (< n 2) n ...) pour n=8 → 44 ✅

Fichier: test-algo-recursifs.lisp
Ligne: 226-233

Code problématique:
```lisp
'(defun tribonacci (n)
   (if (<= n 1)    ; ← Mauvais cas de base
       0           ; ← Retourne toujours 0
```

Solution appliquée:
```lisp
'(defun tribonacci (n)
   (if (< n 2)     ; ← Cas de base correct
       n           ; ← Retourne n (0 ou 1)
```

Résultat:
  ✅ tribonacci(8) = 44 maintenant correct

BUG MOD - Analyse approfondie:
───────────────────────────────────────────────────────────────────────────
Le problème était subtil:

1. Le compilateur reconnaissait '% mais pas 'mod
2. Dans compile-math-func-simplified:
   - (equal func "MOD") appelait compile-arithmetic-binary "%"
   - Mais "MOD" en string, jamais atteint car 'mod arrive comme symbole
   
3. Flux d'exécution:
   (mod n 10)
   → compile-call-simplified avec op='mod
   → Aucune correspondance dans les (eq op 'xxx)
   → Tombe dans le cas par défaut: compile-funcall-simplified
   → Génère (JAL "MOD") au lieu d'inline
   
4. Solution:
   Ajouter (eq op 'mod) → compile-arithmetic-simplified "%"
   Maintenant génère inline: DIV + MFHI

Assembleur généré (AVANT):
  (:JAL "MOD")           ; Appel fonction inexistante
  
Assembleur généré (APRÈS):
  (:MOVE :$V0 :$A0)      ; Arg1 dans $V0
  (:ADDI :$SP -4 :$SP)   ; Sauver $V0
  (:SW :$V0 :$SP 0)
  (:LI 10 :$V0)          ; Arg2 = 10
  (:LW :$T0 :$SP 0)      ; Récupérer arg1
  (:ADDI :$SP 4 :$SP)
  (:DIV :$T0 :$V0)       ; Division
  (:MFHI :$V0)           ; Reste dans $V0


BUG TRIBONACCI - Analyse approfondie:
───────────────────────────────────────────────────────────────────────────
Séquence de Tribonacci correcte: 0, 0, 1, 1, 2, 4, 7, 13, 24, 44...

Cas de base INCORRECT (<= n 1) → 0:
  T(0) = 0 ✅
  T(1) = 0 ✅
  T(2) = 1 ✅
  T(3) = T(2) + T(1) + T(0) = 1 + 0 + 0 = 1 ✅
  T(4) = T(3) + T(2) + T(1) = 1 + 1 + 0 = 2 ✅
  T(8) = 24 ← Valeur avec ce cas de base

Cas de base CORRECT (< n 2) → n:
  T(0) = 0 ✅
  T(1) = 1 ✅ (Différence!)
  T(2) = 1 ✅
  T(3) = T(2) + T(1) + T(0) = 1 + 1 + 0 = 2 ✅
  T(4) = T(3) + T(2) + T(1) = 2 + 1 + 1 = 4 ✅
  T(8) = 44 ← Valeur correcte

La différence: T(1) = 0 vs T(1) = 1 se propage exponentiellement!
