CATÉGORIES D'ÉCHECS:
====================

1. VARIABLES GLOBALES NON DÉFINIES (25+ cas)
   - *REG-V0*, *REG-SP*, *REG-T0*, *REG-S4*, etc.
   - *GLOBAL-CONSTANTS*, *GLOBAL-VARIABLES*
   - *VM-PRIMITIVES*, *BUILT-IN-OPERATORS*
   - *MAXMEM*, *REG-ZERO*

   Solution: Charger ces variables avant la compilation
   ou les définir dans le bootstrap

2. OPÉRATIONS LISTE NON SUPPORTÉES (20+ cas)
   - CAR, CDR, CONS, LIST
   - APPEND (avec nombre variable d'arguments)
   - NULL, MEMBER, ASSOC
   
   Solution: Ajouter ces primitives au compilateur bootstrap

3. OPÉRATIONS HASH-TABLE NON SUPPORTÉES (5+ cas)
   - GETHASH, MAKE-HASH-TABLE
   - HASH-TABLE-COUNT
   - MAPHASH (partiellement supporté)
   
   Solution: Ajouter support hash-tables au bootstrap

4. PRÉDICATS DE TYPE NON SUPPORTÉS (10+ cas)
   - LISTP, INTEGERP, SYMBOLP
   - EQ (comparaison de symboles)
   
   Solution: Ajouter ces prédicats au bootstrap

5. SETF SUR EXPRESSIONS COMPLEXES (10+ cas)
   - (SETF (CAR ...) ...)
   - (SETF (GETHASH ...) ...)
   - (SETF (COMPILER-ENV-STACK-OFFSET ...) ...)
   
   Solution: Supporter SETF généralisé ou utiliser SETQ

6. LABELS AVEC SYMBOLES AU LIEU DE STRINGS (15+ cas)
   - LOOP_START, ELSE, COND_END, etc.
   - Le parser génère ces symboles directement
   
   Solution: Modifier le compilateur pour accepter les symboles
   comme labels et les convertir en strings

7. LOOP AVEC WHILE NON SUPPORTÉ (3+ cas)
   - (LOOP WHILE condition DO ...)
   
   Solution: Ajouter support LOOP WHILE au parser

8. FONCTIONS RÉCURSIVES COMPLEXES (5+ cas)
   - Fonctions qui s'appellent elles-mêmes
   - Mais le compilateur supporte déjà les appels récursifs
   - Problème: les erreurs sont dans d'autres parties
